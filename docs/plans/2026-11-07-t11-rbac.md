Oczekiwane: `main zawiera 40cdcbe` i pusta lista otwartych PR. Jeśli otwarty PR zmienia `deploy/base`, `pyproject.toml`, `docs/architektura.md` albo `README.md`, nie startuj delivery i zgłoś właścicielowi numer PR. Delivery startuje na gałęzi `t11-rbac` (konwencja `txx-krotki-opis` z README).

## Approach

Task 1 należy do stosu Python (test i `pyproject.toml`). Task 2 i Task 3 należą do stosu „pozostałe” (YAML i Markdown). Kolejność 1 → 2 → 3:
- najpierw test. Na klastrze bez T11 nie przechodzi, co pokazuje krok 2 Verification;
- potem manifesty;
- na końcu kontrakt, który opisuje nazwy z Task 1 i Task 2.

Po każdym tasku `make lint`, `make unit` i `make manifests` przechodzą. Klaster, `make up`, przebieg testów RBAC i dowody kryteriów są w Verification. Taski sprawdzają tylko to, co działa bez klastra.

Decyzje wspólne dla tasków:
- Nazwa konta = nazwa workloadu, w namespace workloadu. Konta wszystkich sześciu workloadów powstają w T11, także locust (T18), anomaly-detector (T24) i intruder (T12), bo wymienia je zakres issue.
- Cały RBAC leży w jednym katalogu `deploy/base/rbac/` z jawnym `namespace` w każdym obiekcie, bez transformatora namespace. Konta przyszłych workloadów nie wymagają wtedy zakładania ich katalogów, a recenzent widzi wszystkie uprawnienia w jednym miejscu.
- Deployment ustawia w specyfikacji poda `serviceAccountName` i `automountServiceAccountToken: false`. To drugie ustawienie ma pierwszeństwo przed kontem, więc pod nie dostaje tokenu nawet wtedy, gdy ktoś zmieni mu konto. Tak samo działa już fault-runner.
- Konta `default` w namespace'ach nie zmieniamy (poza zakresem issue). Pod bez `serviceAccountName` wykryje `test_own_deployments_use_their_service_account`.

# (docs/architektura.md, sekcja „RBAC”; manifesty w deploy/base/rbac).
# Uprawnienia sprawdza `kubectl auth can-i` z impersonacją (--as, --as-group),

import json
import os
import shutil
import subprocess

import pytest

pytestmark = pytest.mark.security

KUBE_CONTEXT = os.environ.get("KUBE_CONTEXT", "kind-secure-k8s-aiops")
PART_OF = "app.kubernetes.io/part-of=secure-k8s-aiops"
SA_TOKEN_DIR = "/var/run/secrets/kubernetes.io/serviceaccount"

# Konta z deploy/base/rbac/serviceaccounts.yaml: (namespace, nazwa workloadu).
SERVICE_ACCOUNTS = [
    ("shop", "frontend"),
    ("shop", "orders"),
    ("loadgen", "locust"),
    ("loadgen", "fault-runner"),
    ("aiops", "anomaly-detector"),
    ("intruder", "intruder"),
]
# Wdrożone przed T11; locust, anomaly-detector i intruder dochodzą w T18, T24 i T12.
DEPLOYED_WORKLOADS = {
    ("shop", "frontend"),
    ("shop", "orders"),
    ("loadgen", "fault-runner"),
}

TEAM_IDENTITIES = {
    "developer": ("--as=t11-developer", "--as-group=team:developers"),
    "sre": ("--as=t11-sre", "--as-group=team:sre"),
    "bez-zespolu": ("--as=t11-bez-zespolu",),
}
DEVELOPER_NAMESPACES = ("shop", "loadgen", "aiops")
DEVELOPER_READS = [
    ("list", "pods"),
    ("get", "pods/log"),
    ("watch", "deployments.apps"),
    ("list", "services"),
    ("list", "configmaps"),
    ("list", "events"),
]
DEVELOPER_DENIED = [
    ("get", "secrets"),
    ("list", "secrets"),
    ("create", "pods/exec"),
    ("delete", "pods"),
    ("patch", "deployments.apps"),
    ("create", "configmaps"),

MATRIX = [

        ("developer", verb, resource, namespace, True)
        for namespace in DEVELOPER_NAMESPACES

    ("sre", "list", "pods", None, True),

def kubectl(*args: str, check: bool = True) -> subprocess.CompletedProcess[str]:
    result = subprocess.run(
        ["kubectl", "--context", KUBE_CONTEXT, *args],
        capture_output=True,
        text=True,
        timeout=60,
    )
    if check and result.returncode != 0:
        command = " ".join(args)
        pytest.fail(f"kubectl {command}: kod {result.returncode}, {result.stderr}")
    return result


def get_json(*args: str) -> dict:
    return json.loads(kubectl("get", *args, "-o", "json").stdout)


def identity(who: str) -> tuple[str, ...]:
    if who.startswith("sa:"):
        namespace, name = who.removeprefix("sa:").split("/")
        # Impersonacja konta dodaje grupy system:serviceaccounts(:<namespace>).
        return (f"--as=system:serviceaccount:{namespace}:{name}",)
    return TEAM_IDENTITIES[who]


def can_i(who: str, verb: str, resource: str, namespace: str | None) -> bool:
    # `can-i get pods/log` znaczy pod o nazwie log, więc podzasób idzie osobno.
    name, _, subresource = resource.partition("/")
    args = ["auth", "can-i", verb, name]
    if subresource:
        args.append(f"--subresource={subresource}")
    args += ["-n", namespace] if namespace else ["-A"]
    result = kubectl(*args, *identity(who), check=False)
    answer = result.stdout.strip()
    if answer.startswith("yes"):
        return True
    if answer.startswith("no"):
        return False
    pytest.fail(f"kubectl {' '.join(args)} ({who}): {result.stderr}")


@pytest.fixture(scope="module", autouse=True)
def cluster() -> None:

        pytest.fail("Brak kubectl w PATH: aktywuj mise albo użyj `mise exec --`.")

def test_permission_matrix(who, verb, resource, namespace, expected):

def test_sre_reads_every_listable_resource_except_secrets():
    resources = kubectl("api-resources", "--verbs=list", "-o", "name").stdout.split()
    assert {"pods", "secrets", "deployments.apps"} <= set(resources)
    missing = [
        r for r in resources if r != "secrets" and not can_i("sre", "list", r, None)
    ]
    assert not missing, f"dopisz do deploy/base/rbac/sre-readonly.yaml: {missing}"


@pytest.mark.parametrize(("namespace", "name"), SERVICE_ACCOUNTS)
def test_service_account_does_not_automount_token(namespace, name):
    account = get_json("serviceaccount", name, "-n", namespace)
    assert account.get("automountServiceAccountToken") is False


def test_service_accounts_have_no_rbac_bindings():
    accounts = set(SERVICE_ACCOUNTS)
    namespace_groups = {f"system:serviceaccounts:{ns}" for ns, _ in SERVICE_ACCOUNTS}
    found = []
    for binding in get_json("rolebindings,clusterrolebindings", "-A")["items"]:
        meta = binding["metadata"]
        for subject in binding.get("subjects") or []:
            account = (subject.get("namespace", meta.get("namespace")), subject["name"])
            if (subject["kind"] == "ServiceAccount" and account in accounts) or (
                subject["kind"] == "Group" and subject["name"] in namespace_groups
            ):
                where = f"{meta.get('namespace', '')}/{meta['name']}"
                found.append(f"{binding['kind']} {where}")
    assert not found


def test_own_deployments_use_their_service_account():
    accounts = {}
    for deployment in get_json("deployments", "-A", "-l", PART_OF)["items"]:
        key = (deployment["metadata"]["namespace"], deployment["metadata"]["name"])
        accounts[key] = deployment["spec"]["template"]["spec"].get("serviceAccountName")
    assert DEPLOYED_WORKLOADS <= accounts.keys()
    # Każdy własny Deployment działa na koncie o swojej nazwie z SERVICE_ACCOUNTS.
    wrong = {
        key: account
        for key, account in accounts.items()
        if key not in SERVICE_ACCOUNTS or account != key[1]
    }
    assert not wrong


def test_own_pods_have_no_service_account_token():
    running = get_json(
        "pods", "-A", "-l", PART_OF, "--field-selector=status.phase=Running"
    )
    pods = [p for p in running["items"] if "deletionTimestamp" not in p["metadata"]]
    workloads = {
        (p["metadata"]["namespace"], p["metadata"]["labels"]["app.kubernetes.io/name"])
        for p in pods
    }
    assert DEPLOYED_WORKLOADS <= workloads
    exposed = []
    for pod in pods:
        namespace, name = pod["metadata"]["namespace"], pod["metadata"]["name"]
        for container in pod["spec"]["containers"]:
            target = ["exec", name, "-n", namespace, "-c", container["name"]]

            if "No such file or directory" not in result.stderr:
                output = (result.stdout or result.stderr).strip()
                exposed.append(f"{namespace}/{name}/{container['name']}: {output}")
    assert not exposed

## Assumptions & contingencies

Założenia (właściciel może je zmienić):
- T11 tworzy konta wszystkich sześciu workloadów z issue, także tych, które wdrożą T12, T18 i T24. Te zadania tylko ustawiają `serviceAccountName`.
- Cały RBAC leży w `deploy/base/rbac/`, nie w katalogach workloadów.
- `automountServiceAccountToken: false` jest i na koncie (wymóg issue), i w podzie (pierwszeństwo poda, wzór z fault-runner).
- `team:developers` czyta zdarzenia z obu grup API (`""` i `events.k8s.io`), bo to te same obiekty Event.
- „Odczyt wszystkich zasobów poza secrets” jest wymuszany testem: każdy listowalny zasób żywego klastra musi być czytelny dla `team:sre`. Zadanie dodające CRD dopisuje je do `sre-readonly`. Alternatywą jest sama macierz bez tego testu, ale wtedy rola po cichu odstaje od kontraktu.
- Poza T11: `make test-security` i raporty JUnit/HTML (T26), utwardzenie konta `default`, konta osób (certyfikaty, OIDC) dla grup zespołu. Grupy są sprawdzane tylko impersonacją.

Plan awaryjny:
- `test_sre_reads_every_listable_resource_except_secrets` wypisuje brakujące zasoby, np. CRD, którego nie ma w listach z „Ustalonych faktów”:
  - każda pozycja to nazwa z `kubectl api-resources -o name`: część przed pierwszą kropką to zasób, reszta to grupa API (bez kropki: grupa core `""`). Dopisz zasób do reguły jego grupy w `sre-readonly.yaml`, a dla nowej grupy dodaj regułę `apiGroups: [<grupa>]` z jawną listą zasobów i `verbs: [get, list, watch]`. Nigdy nie używaj `"*"`;
  - potem `make deploy`, powtórz pytest z kroku Verification, w którym test padł, i wymień dopisane zasoby w opisie PR.
- `trivy config` zgłasza HIGH albo CRITICAL dla pliku z `deploy/base/rbac`: popraw regułę według komunikatu, bez wildcardu. Gdy uwaga dotyczy zasobu wymaganego przez issue (np. `pods/log`), zatrzymaj się i zgłoś komunikat.

Dodatkowe błędy z komunikatem `the server doesn't have a resource type` albo z pustym `--subresource` oznaczają błąd w teście: popraw go i powtórz kroki 2–4. Brak oczekiwanej porażki: zatrzymaj się i zgłoś test, który przeszedł mimo braku RBAC.
