## Context

```bash
#!/usr/bin/env bash
# Walidacja manifestów (T06): `kustomize build` każdego overlayu z deploy/overlays → `kubeconform -strict`.
# Uruchamiaj przez `make manifests` (to samo robi job manifests w CI). Sprawdza wszystkie overlaye, czyli katalogi
# z kustomization.yaml (nowy overlay, np. cloud z T29, wchodzi automatycznie), i kończy się kodem 1, gdy któryś
# się nie buduje albo ma zasób niezgodny ze schematem. Zgodny z bash 3.2 (macOS).
# Schematy: Kubernetes w wersji węzłów kind (KIND_NODE_IMAGE z platform/versions.env; lokalizacja `default`
# kubeconform, czyli yannh/kubernetes-json-schema) i CRD z datreeio/CRDs-catalog przypiętego po commicie.
# Zasób bez schematu to błąd: kubeconform działa bez -ignore-missing-schemas.
set -euo pipefail

cd "$(dirname "$0")/.."

# datreeio/CRDs-catalog, commit z 2026-11-05. CRD bez schematu w tym commicie: podbij na nowszy commit z main.
CRDS_CATALOG_COMMIT=c86448cbf1a840ca62d119259864863897c8748a
crds_location="https://raw.githubusercontent.com/datreeio/CRDs-catalog/$CRDS_CATALOG_COMMIT/{{.Group}}/{{.ResourceKind}}_{{.ResourceAPIVersion}}.json"

. platform/versions.env
# kindest/node:v1.36.4@sha256:… → 1.36.4
k8s_version=${KIND_NODE_IMAGE#*:v}
k8s_version=${k8s_version%%@*}
case $k8s_version in
  '' | *[!0-9.]*)
    echo "Nie da się odczytać wersji Kubernetes z KIND_NODE_IMAGE=$KIND_NODE_IMAGE." >&2
    exit 1
    ;;
esac

total=0
failed=0
for kustomization in deploy/overlays/*/kustomization.yaml; do
  [ -f "$kustomization" ] || continue
  overlay=${kustomization%/kustomization.yaml}
  total=$((total + 1))
  echo "== $overlay (Kubernetes $k8s_version)"
  # pipefail: nieudany kustomize build daje pusty strumień, który kubeconform uznałby za poprawny.
  if ! kustomize build "$overlay" | kubeconform -strict -summary \
    -kubernetes-version "$k8s_version" \
    -schema-location default \
    -schema-location "$crds_location" \
    -; then
    echo "BŁĄD: $overlay" >&2
    failed=$((failed + 1))
  fi
done

if [ "$total" -eq 0 ]; then
  echo "Brak overlayów: deploy/overlays/*/kustomization.yaml." >&2
  exit 1
fi
if [ "$failed" -gt 0 ]; then
  echo "Błędne overlaye: $failed z $total." >&2
  exit 1
fi
echo "Wszystkie overlaye poprawne ($total)."
```

### Task 3: Workflow CI i Dependabot
**Commit:** ci: workflow CI (lint, unit, secrets, manifests) i Dependabot

**Files:**
- Create: `.github/workflows/ci.yml`
- Create: `.github/dependabot.yml`

Interfejs z Task 1: każdy job woła jeden cel make (`make lint`, `make unit`, `make gitleaks`, `make manifests`), a kod 0 oznacza sukces. Ruleset (sekcja „Po dostarczeniu”) wymaga kontroli o nazwach jobów, więc identyfikatory jobów to dokładnie `lint`, `unit`, `secrets`, `manifests`, bez klucza `name:` w jobach.

1. Utwórz `.github/workflows/ci.yml` z poniższą treścią. Uzasadnienie decyzji:
   - `persist-credentials: false`: żaden job nie pushuje, więc token nie zostaje w `.git/config`;
   - `fetch-depth: 0` tylko w `secrets`, bo gitleaks potrzebuje pełnej historii;
   - `UV_PYTHON_DOWNLOADS: never`: uv bierze wyłącznie Pythona z mise i nie pobiera własnego;
   - `ubuntu-24.04` zamiast `ubuntu-latest`: obraz runnera się nie zmienia bez PR;
   - bez filtrów `paths`, bo wymagana kontrola, która się nie uruchomi, zablokowałaby PR na zawsze.

```yaml
# CI (T06): każdy PR i każdy push na main. Joby lint, unit, secrets i manifests to wymagane
# kontrole rulesetu gałęzi main: zmiana nazwy joba wymaga zmiany rulesetu.
# Każdy job uruchamia cel make, który działa też lokalnie. Narzędzia instaluje jdx/mise-action
# z mise.toml (tylko te, których job potrzebuje); wersja mise = min_version z mise.toml.
# Akcje przypięte po pełnym SHA commita z komentarzem wersji (lekcja z kompromitacji trivy-action,
# CVE-2026-33634); repozytorium wymaga takiego przypięcia (sha_pinning_required), podbija je Dependabot.
name: CI

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  lint:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: jdx/mise-action@f5be966e4a917d54244728e6a5fdcd1d93a35e6c # v5.2.6
        with:
          version: "2026.10.13"
          install_args: ruff
      - run: make lint

  unit:
    runs-on: ubuntu-24.04
    env:
      # Tylko Python z mise.toml: uv nie pobiera własnego interpretera.
      UV_PYTHON_DOWNLOADS: never
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: jdx/mise-action@f5be966e4a917d54244728e6a5fdcd1d93a35e6c # v5.2.6
        with:
          version: "2026.10.13"
          install_args: python uv
      - run: make unit

  secrets:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          # Pełna historia: gitleaks skanuje wszystkie commity osiągalne z HEAD.
          fetch-depth: 0
          persist-credentials: false
      - uses: jdx/mise-action@f5be966e4a917d54244728e6a5fdcd1d93a35e6c # v5.2.6
        with:
          version: "2026.10.13"
          install_args: gitleaks
      - run: make gitleaks

  manifests:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: jdx/mise-action@f5be966e4a917d54244728e6a5fdcd1d93a35e6c # v5.2.6

          version: "2026.10.13"

```

## Assumptions & contingencies

Założenia (właściciel może je zmienić):
- Ruleset nie ma wyjątków, także dla admina. W nagłym przypadku właściciel przełącza go na `Disabled` w Settings → Rules → Rulesets. Ruleset powstaje przed scaleniem T06, więc już PR T06 wymaga zatwierdzenia `DreadGoblin`.
- Flagi rulesetu zostają z domyślnymi wartościami GitHuba:
  - `dismiss_stale_reviews_on_push: false`: zatwierdzenie nie znika po nowym commicie;
  - `strict_required_status_checks_policy: false`: gałąź nie musi być aktualna względem `main`;
  - `required_review_thread_resolution: false`.
- gitleaks skanuje historię HEAD (w PR: `main` + commity PR), a nie `--all`. Sekret wypchnięty na inną gałąź nie blokuje cudzych PR; takie przypadki obejmuje secret scanning GitHuba (włączony).
- W CI mise ma wersję `2026.10.13` (= `min_version`), a Dependabot ma cooldown 7 dni. Piny wybrano w dniu planu: najnowsze wydania checkout (v7.0.1) i mise-action (v5.2.6).
- PR testowe zostają w historii repozytorium jako zamknięte, a commit z losowym, nigdy ważnym kluczem jest osiągalny przez `refs/pull/<PS>/head`. Gałąź `main` go nie zawiera.

Plan awaryjny:
- Push gałęzi `t06-test-sekret` odrzucony przez push protection (`GH013`, „Push cannot contain secrets”):
  - z adresu `…/security/secret-scanning/unblock-secret/<id>` w komunikacie weź `<id>`;
  - uruchom `gh api --method POST "repos/$R/secret-scanning/push-protection-bypasses" -f reason=used_in_tests -f placeholder_id=<id>` i powtórz push;
  - gdy API zwróci błąd, właściciel otwiera ten adres w przeglądarce i wybiera „It's used in tests”.
- `unit` w CI pada na testach zależnych od czasu (`test_faults.py` CPU/RSS, `test_cli.py` czas skoku), a lokalnie przechodzi:
  - jeden raz `gh run rerun <run> --repo "$R" --failed`;
  - ponowny błąd tego samego testu: zatrzymaj się i zgłoś nazwę testu i log. Testów w T06 nie zmieniaj.
- `jdx/mise-action` nie instaluje narzędzia (HTTP 403/429 z API GitHuba, błąd pobierania): jeden raz `gh run rerun --failed`; powtórka: zatrzymaj się i zgłoś log kroku.
- Pierwszy przebieg CI odrzuca akcję jako nieprzypiętą: sprawdź, czy SHA w `ci.yml` mają 40 znaków i zgadzają się z „Ustalonymi faktami”. Poprawka idzie do gałęzi `$B`, bez wyłączania `sha_pinning_required`.
- `kubeconform` zgłasza `could not find schema for <Kind>`, bo inne scalone zadanie dodało CRD do overlayu:
  - ustaw `CRDS_CATALOG_COMMIT` na `gh api repos/datreeio/CRDs-catalog/commits?per_page=1 --jq '.[0].sha'` i powtórz;
  - gdy katalog nie ma tego schematu, zatrzymaj się i zgłoś rodzaj zasobu. Nie dodawaj `-ignore-missing-schemas` ani `-skip`.
- `gh api … rulesets` zwraca 422: zatrzymaj się i zgłoś treść błędu. Nie usuwaj reguł ani wymaganych kontroli.
- `gh pr checks --required` nie pokazuje czterech kontroli: porównaj `context` w `gh api "repos/$R/rulesets"` z nazwami z `gh pr checks`, popraw ruleset przez `gh api --method PUT "repos/$R/rulesets/<id>" --input …` z tą samą treścią i poprawionymi nazwami, potem powtórz krok.
- `mergeStateStatus: UNKNOWN`: GitHub jeszcze liczy stan. Odczekaj 10 s i odczytaj ponownie, najwyżej 3 razy.
- Bezpośredni push na `main` przyjęty (`exit=0`): ruleset nie działa. Zatrzymaj się i zgłoś wynik `gh api "repos/$R/rules/branches/main"`. Pustego commita nie cofaj.
- zizmor zgłasza uwagi:
  - `unpinned-uses`, `artipacked`, `excessive-permissions`, `ref-version-mismatch` i `dependabot-cooldown` przeczą wymaganiom planu: popraw `ci.yml` albo `dependabot.yml`;
  - pozostałe uwagi wypisz w opisie PR w sekcji „Uwagi zizmor” bez zmian w plikach.
